## Проект лабораторной работы

**Тема проекта:** влияние сезонных и погодных условий на спрос на прокат велосипедов.

**Датасет:** Bike Sharing Dataset, UCI Machine Learning Repository.

Основной файл проекта — `hour.csv`, содержащий почасовые данные о количестве аренд велосипедов.

## Лабораторная работа №3

**Профилирование и качество данных: переход от raw к staging**

В лабораторной работе выполнено профилирование исходного набора данных, определены правила качества и сформированы подготовленные слои `staging` и `quarantine`.

### Источник данных

Исходные данные читаются напрямую из S3 через DuckDB:

```text
s3://raw/bike-sharing/ingested_on=2026-10-18/hour.csv

Raw-слой не изменяется.

Профилирование
Для исходного набора данных выполнены:
- определение количества строк и столбцов;
- проверка типов и примеров значений;
- анализ пропусков;
- проверка дубликатов по ключу dteday + hr;
- определение диапазона дат;
- анализ распределения количества аренд по часам.

Результат профилирования:
Строк: 17 379
Столбцов: 18
Период: 2011-01-01 — 2012-12-31
Дубликаты по dteday + hr: 0
Пропуски в проверяемых полях: 0

Правила качества
Реализовано 7 правил качества данных:
- UQ01 — уникальность dteday + hr;
- CM01 — полнота ключевых полей;
- RG01 — cnt >= 0;
- RG02 — 0 <= hr <= 23;
- CAT01 — допустимые значения season;
- CAT02 — допустимые значения weathersit;
- CONS01 — casual + registered = cnt.
Все правила проверены на полном наборе данных.

Результат:
7 / 7 правил: PASS
Нарушения: 0

Подготовленные данные
По результатам проверок сформированы:

s3://staging/bike-sharing/source_ingested_on=2026-10-18/quarantine.parquet

## Лабораторная работа № 4

### Построение аналитической витрины Bike Sharing

**Авторы:** Попов Никита, Гордий Владимир  
**Группа:** ИВТ-241

В лабораторной работе реализован переход от слоя `staging` к аналитической витрине `mart` с использованием DuckDB и хранилища S3.

**Цель работы:** построить аналитическую витрину для анализа зависимости количества аренд велосипедов от сезона и погодных условий.

**Входные данные:**
`s3://staging/bike-sharing/source_ingested_on=2026-10-18/staging.parquet`

**Результат:**
`s3://mart/bike-sharing/source_ingested_on=2026-10-18/hourly_rentals.parquet`

**Выполненные задачи:**
- Описана модель аналитической витрины и её гранулярность.
- Выполнено сопоставление полей `staging` и `mart`.
- Сохранены данные и флаги качества.
- Реализованы проверки структуры, ключей, пропусков и диапазонов значений.
- Подготовлен групповой анализ аренд по сезонам и погодным условиям.

**Результаты проверок:**
- Строк в `staging`: 17 379.
- Строк в `mart`: 17 379.
- Проверки ключа `dteday + hr` на NULL и дубликаты пройдены.
- Все 12 проверок витрины завершились успешно.

**Файлы лабораторной работы:**
- `notebooks/build_mart.ipynb` — построение и проверка аналитической витрины.
- `docs/mart.md` — описание модели, сопоставления полей, проверок и ограничений.
